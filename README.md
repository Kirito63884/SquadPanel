# SquadPanel

Самостоятельно устанавливаемая (self-hosted) панель для админов серверов **Squad**.
Модель аккаунтов, организаций и ролей — по образцу [WARCON](https://github.com/warcon-app/warcon),
вид — лёгкий тёмный интерфейс. Логика RCON и парсинга логов портирована из
[SquadJS](https://github.com/Team-Silver-Sphere/SquadJS) (см. `THIRD_PARTY_NOTICES.md`).

> Статус: 0.3. Живой мониторинг, чат и события, плагины, аккаунты, организации, роли, действия и журнал аудита,
> а также **киты и отряды, Steam, история игроков, боевая статистика из SquadGame.log (локально или SFTP),
> профиль игрока, лестница админов и экспорт Admins.cfg**. Серверы и настройки хранятся в базе.

## Что есть

- **Аккаунты** (Better Auth): вход по логину или email + пароль, мастер первого запуска,
  выход, смена пароля (остальные сессии завершаются), список сессий и их завершение,
  отключение пользователей владельцем сайта, защита от перебора (5 попыток на логин /
  20 на IP за 15 минут → блокировка на 15 минут). Задел под вход через Discord.
- **Организации**: владельцы и участники, ссылки-приглашения (роль в организации + роль на серверах,
  лимит использований, срок действия, отзыв).
- **Роли на серверах и лестница админов**: Владелец организации > Старший админ (50) > Тех. админ (45) >
  Админ (40) > Модератор (30) > Стажёр (20) > Наблюдатель (10) > Только чат (5) + свои роли со своим рангом.
  У каждой роли — **лимит бана** (с v0.5.1: Старший и Админ — навсегда, Модератор — до 14d, Стажёр — до 3d, остальные — без банов),
  проверяется на сервере; в окне бана видны только разрешённые сроки. Владелец организации
  редактирует права ролей галочками и ранги на вкладке «Лестница». Право `members.manage` ограничено рангом:
  выдавать/снимать можно только роли **ниже своей** и только тем, чья роль ниже вашей (проверяется на сервере,
  покрыто тестами). Права: `view` (только статус сервера), `players.view` (игроки, отряды, профили),
  `chat.read`, `bans.manage` (настройки банлиста и шаблоны), `players.warn`, `players.kick`,
  `players.ban`, `players.move`, `squads.manage`, `map.change`, `broadcast`, `console.raw`,
  `plugins.manage`, `servers.manage`, `audit.read`, `members.manage`. Проверяются на сервере —
  в каждом маршруте веб-панели и ещё раз в API воркера.
- **Игроки на сервере**: значки китов (SL, CMD, MED, RIF, CRW, PLT, …) с названием роли, отряд и лидер,
  команда/фракция; заголовки отрядов — номер, название, размер, замок, создатель и лидер с аватаром.
  Клик по заголовку — **карточка отряда** (состав, роли, действия), клик по игроку — **профиль игрока**.
- **Профиль игрока** (с сервера, из поиска Ctrl+F и из истории): аватар, ники, EOS/Steam ID с копированием,
  Steam (ник, дата аккаунта, часы в Squad, VAC/игровые баны), наше время и сессии, K/D, тимкиллы, поднятия,
  любимое оружие, килл-фид, действия админов из журнала, заметки (видны админам организации).
- **Steam** (`STEAM_API_KEY`, необязательно): сводки и баны пачками по 100, часы Squad (appid 393380)
  только у открытых профилей, кэш в базе на 24 ч, ограничение частоты запросов. Игроки только с EOS (Epic)
  и закрытые профили обрабатываются аккуратно — «скрыто»/«только EOS».
- **База игроков** (`/players`, как в WARCON): все игроки, которых видели ваши серверы, — поиск по нику,
  прошлым никам, EOS/Steam ID; фильтры онлайн/все/забанены/наблюдение и по серверу; сортировка по заходам,
  времени в игре, сессиям, K/D/TK; страницы. Счётчики варнов/банов/киков/заметок, аватар и страна из Steam.
- **Автоматизация** (`/servers/:id/automation`): лимит тимкиллов, AFK, объявления по таймеру, сброс пустого
  сервера, свои чат-команды, отсчёт перед рестартом; у каждого правила — пробный прогон за 24 ч.
- **Голосование за смену карты** (кнопка админа и `!skip`, голоса `!yes`/`!no` или `1`/`2`).
- **Наблюдение (watchlist)** и **сохранённые сообщения** организации.
- **История игроков**: все ID и ники, сессии, наигранное время на ваших серверах (вкладка «История» на
  странице «Игроки»). Пишется воркером в базу через внутренний API панели.
- **Боевая статистика из SquadGame.log**: ранения, смерти, поднятия, тимкиллы → K/D, оружие, килл-фид.
  Источник лога — локальный файл или **SFTP** (пароль или ключ, секреты зашифрованы, переподключение,
  ротация файла), кнопка «Проверить» в настройках сервера. Без источника на странице сервера — подсказка.
- **Действия из панели** (правый клик по игроку и панель над серверами): варн, кик (причина),
  бан (причина + срок: 1h…30d, навсегда или свой), перевод в другую команду, удаление из отряда,
  роспуск отряда, объявление, смена текущей / следующей карты (список слоёв из `ListLayers`),
  RCON-консоль (`console.raw`), **снять с командира** (`AdminDemoteCommander`; по желанию — запасной
  вариант через смену команды), **варн отряду**, **перевод отряда** в другую команду (по одному бойцу,
  ~3 команды в секунду, результат по каждому). У каждого действия — своё право и запись в журнале.
  У каждого действия — окно подтверждения, **Enter** подтверждает, **Esc** отменяет.
- **Банлист организации** (`/bans`): поиск, фильтр активные/истекшие/снятые, кто выдал, причина, срок;
  изменение срока/причины и разбан (свои баны или выданные младшими по рангу); бан на все серверы организации
  или на один; **бан по EOS/Steam ID** (игрок может быть офлайн — воркер кикает его при заходе, пока бан
  активен); сообщение при бане с `{reason} {expires} {duration} {appeal}` и ссылкой на обжалование;
  выгрузка `Bans.cfg` (только скачивание — на сервер ничего не пишется). Баны хранит панель, поэтому их
  можно снять; по желанию (настройка) дублировать в игровой `Bans.cfg` через `AdminBan`.
- **Варны со сроком** (по умолчанию 30d, настраивается): активные/истекшие в профиле и метки `W` у ников.
- **Шаблоны причин** (текст + срок) для бана, варна и кика — общие для организации.
- **Отряды**: меню по правому клику на заголовке отряда (карточка, варн, перевод, сброс названия
  `AdminRenameSquad`, роспуск `AdminDisbandSquad`). Закрыть/открыть отряд через RCON нельзя — такой
  админ-команды в Squad нет.
- **Режим «только чтение»** для каждого сервера: панель и плагины не отправляют изменяющих команд;
  в консоли работают только читающие (`ListPlayers`, `ShowServerInfo`…). Переключает владелец
  организации в настройках сервера. Импортированные и новые RCON-серверы по умолчанию — только чтение.
- **Журнал аудита**: входы (и неудачные), изменения пользователей, серверов, участников и ролей,
  каждая игровая команда — кто, сервер, цель, данные, результат (успех/отказ/ошибка), ответ RCON,
  время выполнения. Фильтры, выгрузка CSV и JSON. Пароли и токены в журнал не попадают.
- **База данных**: PostgreSQL (через `DATABASE_URL`) или встроенная **PGlite** — та же схема, без установки,
  данные в `SQUADPANEL_DATA_DIR/pglite`. Миграции Drizzle применяются автоматически.
- **Пароли RCON шифруются** AES-256-GCM ключом из `SQUADPANEL_SECRET`.
- **Экспорт Admins.cfg** («Участники и роли» → Admins.cfg): группы и `Admin=<SteamID|EOS>:<группа>`
  из ролей панели, для всей организации или одного сервера, предпросмотр, копирование и скачивание.
  Панель **никогда не записывает** файл на игровой сервер. Игровые ID участники указывают в «Настройках».
- RCON-клиент, парсер логов, воркер с плагинами `!report` / `!admin` / приветствие, Discord-уведомления, живой поток (SSE),
  русский / английский интерфейс, демо-сервер с фейковыми игроками.

## Структура

```
packages/rcon      RCON-клиент + парсеры ответов + фейковый сервер для тестов
packages/logs      парсер SquadGame.log + tail
packages/core      база (Drizzle: PostgreSQL/PGlite), аккаунты, права, аудит, шифрование, действия
packages/notify    Discord: маршрутизация, эмбеды, очередь, бот/webhook
apps/worker        фоновый процесс: соединения, состояние, плагины, внутренний API (:3101)
apps/worker/plugins/   report, admins, welcome — см. docs/plugins.md
apps/web           веб-панель SvelteKit (:5173 в dev, :3000 в prod); владеет базой
config/            servers.example.json — старый формат, импортируется при первом запуске
docs/              squad-research.md, plugins.md, deploy.md, discord.md (бот и каналы)
```

Веб-панель владеет базой; воркер получает от неё список серверов (пароли — в зашифрованном виде)
по внутреннему API и отчитывается о действиях плагинов в журнал. Токен между ними выводится из `SQUADPANEL_SECRET`.

## Быстрый старт на Windows

Нужен **Node.js 24+** (`node -v`). Самый простой путь — дважды щёлкнуть **`start.bat`**:
он при первом запуске поставит зависимости, запустит панель и откроет http://127.0.0.1:5173.

То же вручную:

```powershell
cd C:\Users\PC\Desktop\SquadPanel.pro
npm install
npm run dev
```

Откройте http://127.0.0.1:5173 — запустится **мастер первой настройки**:

1. **Владелец** — логин и пароль (≥ 10 символов) владельца сайта.
2. **Организация** — название вашего клана/проекта.
3. **Сервер** — по желанию: хост, RCON-порт и пароль, кнопка «Проверить подключение» (выполняет
   только `ShowServerInfo`). Галочка «Только чтение» включена по умолчанию.

Если в `.env` заданы `SQUAD_RCON_*` или есть `config/servers.json` (как в версии 0.1), мастер предложит
импортировать эти серверы — тоже в режиме «только чтение». Дальше серверы живут в базе и правятся в панели;
старые файлы больше не читаются.

Посмотреть панель с «живыми» игроками без своего сервера: `npm run demo` (мастер предложит демо-сервер,
на нём можно смело пробовать кики, баны и смену карты).

### Ключ и данные

- При первом запуске, если `SQUADPANEL_SECRET` не задан, панель создаёт ключ в `data/secret.key` и пишет
  предупреждение. **Сохраните этот файл** (или задайте `SQUADPANEL_SECRET` в `.env`): без него сохранённые
  пароли RCON не расшифровать, а все сессии станут недействительны.
- Встроенная база лежит в `data/pglite`. Резервная копия — остановить панель и скопировать папку `data`.
- Для PostgreSQL укажите `DATABASE_URL=postgres://user:pass@host:5432/db` — таблицы создадутся сами.

### Пригласить админов

«Участники и роли» → «Приглашения» → выберите роль на серверах (например, «Оператор») → «Создать ссылку» →
отправьте ссылку. Перешедший создаёт учётную запись и сразу получает доступ. Права ролей меняются на вкладке
«Роли и права», роль конкретного человека на конкретном сервере — на вкладке «Участники».

### Продакшен без Docker

```powershell
npm run build
npm start          # воркер + веб на http://127.0.0.1:3000
```

Чтобы открыть панель с других машин: `HOST=0.0.0.0` и `ORIGIN=http://<ip-или-домен>:3000`
(или ваш https-адрес за обратным прокси).

## Отдельный VPS (Docker, HTTPS)

Рекомендуемый способ для постоянной работы — свой VPS (Ubuntu 22.04/24.04, 1–2 vCPU, 2 ГБ RAM)
отдельно от игрового сервера. Подробно — **[docs/deploy.md](docs/deploy.md)**. Коротко, с Windows:

```bat
deploy\upload.bat          :: упаковать проект, отправить по scp и установить на VPS
```

На VPS это `deploy/install.sh`: Docker, `/opt/squadpanel/.env` со случайными секретами (chmod 600),
`ufw` (22/80/443), стек `postgres + web + worker + caddy` (автоматический HTTPS по домену или HTTP по IP),
ежедневные бэкапы и ссылка первого запуска `https://домен/setup?token=…`. Дальше — команда `squadpanel`
(`status`, `logs`, `backup`, `restore`, `update`, `rollback`, `import`, `set-domain`).
Перенос данных с ПК: `npm run db:export` → `squadpanel import файл.json.gz` (секрет переносится вместе с данными).

Вручную: `docker compose --env-file /путь/.env up -d --build` (переменные — `deploy/env.example`).
Наружу публикуется только Caddy (80/443); Postgres, web и API воркера — во внутренней сети Docker.

## Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `SQUADPANEL_SECRET` | создаётся в `data/secret.key` | ключ шифрования паролей RCON, сессий и токена web↔воркер (≥ 32 символов) |
| `DATABASE_URL` | — (встроенная PGlite) | PostgreSQL |
| `SQUADPANEL_DATA_DIR` | `data` | база PGlite, `secret.key`, данные плагинов |
| `SQUADPANEL_WEB_URL` | dev: `http://127.0.0.1:5173`, prod: `http://127.0.0.1:$PORT` | адрес панели для воркера |
| `WORKER_URL` | `http://127.0.0.1:3101` | адрес воркера для панели |
| `PORT`, `HOST`, `ORIGIN` | `3000`, `127.0.0.1`, `http://127.0.0.1:3000` | веб-сервер в продакшене |
| `SQUAD_RCON_*`, `SQUADPANEL_CONFIG`, `SQUADPANEL_DEMO` | — | только для импорта в мастере первого запуска |
| `SQUADPANEL_SETUP_TOKEN` | — | если задан, мастер первого запуска открывается только по `/setup?token=…` (ставит install.sh) |
| `ADDRESS_HEADER`, `XFF_DEPTH` | — | за обратным прокси: реальный IP клиента (в docker-compose: `X-Forwarded-For`, `1`) |
| `STEAM_API_KEY` | — | Steam Web API: аватары, часы, баны (без ключа — без данных Steam) |
| `DISCORD_CLIENT_ID/SECRET` | — | задел под вход через Discord (пока выключен). Уведомления настраиваются в панели, не здесь |

`WORKER_API_TOKEN` из версии 0.1 больше не нужен.

## Обновление с 0.5.0 до 0.5.1

Замените файлы (кроме `.env` и `data/`), `npm install`, `npm run build`, перезапустите. Миграция `0007_discord_v2`
применится автоматически: добавит настройки оформления Discord и обновит лимиты банов встроенных ролей
(стажёр — 3d + право бана, модератор — 14d, админ — навсегда). Свои роли не меняются.

## Обновление с 0.4

Остановите панель, сделайте копию папки `data`, замените файлы (`data` и `.env` не трогайте), запустите
`start.bat`. Миграция `0006_automation` добавит базу игроков (`player_servers`, счётчики K/D/TK), правила
автоматизации, наблюдение, сохранённые сообщения и настройки статуса Discord-бота. Данные не удаляются;
база игроков заполняется из банов, варнов, сессий и боевых событий, которые уже есть. Все правила
автоматизации по умолчанию выключены. Право `automation.manage` получают Старший и Тех. админ.

## Обновление с 0.3

Остановите панель, сделайте копию папки `data`, замените файлы (`data` и `.env` не трогайте), запустите
`start.bat`. Миграция `0005a_moderation` добавит таблицы банов, варнов и шаблонов, лимиты банов ролям и роли
«Тех. админ» и «Только чат». Данные не удаляются; всем существующим ролям добавляется `players.view`
(они видят то же, что и раньше), у Модератора права бана **не** появляются автоматически — включите
галочкой, если нужно. Шаблоны причин по умолчанию добавятся каждой организации.

## Обновление с 0.2

Остановите панель, замените файлы (папку `data` и `.env` не трогайте!), запустите `start.bat`.
Миграция `0001_staff_players_logs` применится сама и **не удаляет данные**: пользователи, организации,
серверы, приглашения и журнал остаются. Роли переименовываются по лестнице: «Оператор» → «Модератор»
(права сохраняются), «Администратор» → «Админ», добавляются «Старший админ» и «Стажёр»; свои роли получают
ранг 15. Сделайте копию папки `data` перед обновлением — на всякий случай.

## Лог сервера (SquadGame.log)

Настройки сервера → «Источник логов»:

- **Локальный файл** — если панель стоит на той же машине, что и сервер:
  `…\SquadGame\Saved\Logs\SquadGame.log`.
- **SFTP** — для хостинга: хост, порт (обычно 22 или порт из панели хостинга), пользователь, пароль или
  приватный ключ (+ пароль ключа), путь к `SquadGame.log`. Пароль/ключ шифруются в базе и больше не показываются.
  Нажмите «Проверить» — панель прочитает конец файла и покажет, сколько боевых строк распознано.

Панель только **читает** лог (раз в ~2 с дочитывает новые строки; при перезапуске сервера/ротации
начинает файл заново). Формат боевых строк взят из SquadJS; тесты идут на синтетическом логе
(`packages/logs/test/fixtures`, помечен как не проверенный на живом сервере).

## Проверка RCON

Только читающие команды (`ShowServerInfo`, `ShowCurrentMap`, `ShowNextMap`, `ListPlayers`, `ListSquads`):

```powershell
$env:SQUAD_RCON_HOST="1.2.3.4"; $env:SQUAD_RCON_PASSWORD="..."; npm run rcon:probe -- --listen 30 --layers
```

| `npm test` | тесты: RCON, логи (в т.ч. SFTP-сервер в процессе), права и лестница, миграция 0.2→0.3, история, K/D, Steam (мок), действия против фейкового сервера |
| `npm run typecheck` | проверка типов (включая svelte-check) |
| `npm run db:export` | выгрузить базу (PGlite или Postgres) с секретом в `squadpanel-export-ДАТА.json.gz` — для переноса на VPS |
| `npm run db:generate` | сгенерировать миграцию после изменения схемы (`packages/core/src/db/schema.ts`) |

## Безопасность

- Порт RCON (21114) открывайте только для IP, где стоит панель: пароль RCON идёт по сети открытым текстом.
- Squad разрешает мало одновременных RCON-подключений — панель держит **одно** на сервер.
- В интернет панель выставляйте только за HTTPS (обратный прокси) и с `ORIGIN` = публичный адрес.
- Боевой сервер держите в режиме «только чтение», пока не выдадите роли и не проверите всё на демо.

## Дорожная карта

1. Вход через Discord (уведомления в каналы уже есть: меню «Discord», см. docs/discord.md).

3. Чтение логов по FTP (сейчас — локальный файл и SFTP).
4. Готовые образы (registry) вместо сборки на VPS.
